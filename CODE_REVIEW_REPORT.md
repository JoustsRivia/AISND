## 二、架构质量评估

### 优点

1. **隔离层设计（shared/ → cloudfunctions/*/helpers/）**：通过 `bundle-db-base.js` 将 `dbBase.js`、`userBase.js`、`rateLimiter.js` 同步到 18 个云函数，所有副本经校验无漂移。迁移到自有服务器时仅需重写 3 个 shared 文件，业务代码零改动。—— **符合 AGENTS.md §1②"为下一个需求设计"**
2. **API 传输抽象（utils/api.js）**：321 行封装全部 70+ 后端接口，`invoke()` 在云函数和 `wx.request` 之间切换时调用方无感知，注释明确标注迁移策略。—— **符合 AGENTS.md §1②**
3. **RBAC 数据范围统一注入（shared/dbBase.js）**：`scopeFilter` / `allowedOrgIds` 纯函数 + `GLOBAL_ROLES` / `UNIT_ROLES` 白名单 → 各业务云函数统一调用，避免权限判断分散到 18 个函数。—— **符合 AGENTS.md §1④"直取核心"**
4. **CI 门禁链完善**：语法检查、隔离层防漂移、前端零直连接入、云函数构建验证、硬编码凭据扫描、MongoDB 迁移演练——5 层防御。—— **符合 AGENTS.md §2 五步闭环中的"交接"**

## 三、问题发现清单

### 🔴 严重（影响安全或核心架构，须优先修复）

#### SEC-01 | SHA1 密码哈希（密码学强度不足）
| 状态   | ✅ 已完成（已实施，详见迭代记录 / 隔离层单一源） |

| 项    | 内容                                                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| 文件   | `cloudfunctions/auth/index.js` L53、`cloudfunctions/system/index.js` L56                                                      |
| 代码   | `crypto.createHash('sha1').update('tms_' + p).digest('hex')`                                                                 |
| 风险   | SHA1 已被 NIST 于 2011 年弃用；静态盐 "tms\_" 全仓库可见，彩虹表可预计算；碰撞攻击成本极低                                                                   |
| 修复   | 改用 `bcrypt` 或 `scrypt`（Node 内置 `crypto.scrypt` 需 Node≥10）；至少改用 `crypto.pbkdf2('sha512', p, salt, 100000, 64)`，salt 按用户独立随机生成 |
| 整改难度 | **低** — 单一文件修改，单向替换                                                                                                          |

#### SEC-02 | 17/18 个云函数未接入限流中间件
| 状态   | ✅ 已完成（已实施，详见迭代记录 / 隔离层单一源） |

| 项    | 内容                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------------- |
| 状态   | `shared/rateLimiter.js` 已实现并同步到所有云函数 helpers/，但仅有 `system` 云函数在其 index.js 入口调用 `createRateLimiter().wrap()` |
| 影响   | auth（登录/注册）、tool（查询/录入）、borrow（领用归还）等高频端点无频率控制，可被批量脚本消耗云函数配额或实施暴力破解                                         |
| 根因   | rateLimiter 作为"基础设施"被正确分发，但未规定为云函数入口的必选项，形成"有工具但没装"的半成品状态                                                   |
| 修复   | 为每个云函数 index.js 入口包装 `wrap(handler, action)`，至少覆盖认证类（auth）和写操作类（borrow/scrap/purchase/store）端点              |
| 整改难度 | **中** — 18 个文件需逐个接入，但改动模板相同                                                                                 |

#### RATE-01 | auth 云函数无登录频率限制
| 状态   | ✅ 已完成（已实施，详见迭代记录 / 隔离层单一源） |

| 项    | 内容                                                                                                             |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| 位置   | `cloudfunctions/auth/index.js` — login、register、signin 三个入口                                                    |
| 影响   | 无任何频率控制 → 暴力破解密码仅受微信云函数并发限制（远高于合理阈值）                                                                           |
| 修复   | 在 `auth/index.js` 的 `exports.main` 用 rateLimiter 包装 `login`/`signin`/`register` actions；登录端点限流应设为窗口 60s 内 ≤5 次 |
| 整改难度 | **低** — 单文件接入限流中间件                                                                                             |

#### CACHE-01 | 内存策略缓存无主动 TTL 轮换
| 状态   | ✅ 已完成（已实施，详见迭代记录 / 隔离层单一源） |

| 项    | 内容                                                                                |
| ---- | --------------------------------------------------------------------------------- |
| 位置   | `cloudfunctions/system/index.js` L14–23（`__retentionCache`）、L36–45（`__rateCache`） |
| 问题   | 缓存仅在 `useCache=true` 且 `Date.now() - ts < 60000` 时复用；云函数实例被冻结再恢复时可能持有超过 60s 的过期缓存 |
| 修复   | 使用 `setInterval(() => { clearRetentionCache(); clearRateCache(); }, 60_000)` 主动失效 |
| 整改难度 | **低** — 3 行代码                                                                     |

#### ARCH-01 | scaffold 模板未使用隔离层 dbBase

| 整改难度 | **低**                                                                     |
